# TrainOS — первый аудит проекта

Дата проверки: 2026-10-19

## Объём проверки

- Исходный архив: `trainos.zip`.
- Проверены 2,107 Python-модулей под `trainos/kernel`.
- Проверены все существующие тесты в `trainos/tests`.
- Проверены синтаксис Python, импортируемость модулей и тесты Stage 1–38.
- Подготовленный архив не содержит служебных каталогов `.venv`, `.git`, `__pycache__`, `.pytest_cache`, `.history` и файлов `.DS_Store`. Исходный архив пользователя не изменялся.

## Исправления

1. `trainos/kernel/scheduler/priority.py`
   - Удалён случайно продублированный код `TaskQueue`, из-за которого `from __future__ import annotations` находился в середине файла и ломал компиляцию проекта.

2. `trainos/kernel/scheduler/task_queue.py`
   - Добавлен стабильный FIFO-порядок при одинаковых приоритете и времени.
   - Добавлены `peek()`, `__len__()` и `pop_due(now)`.
   - `pop_due()` позволяет выбрать готовую задачу, не блокируясь задачей с более высоким приоритетом, но будущим временем.

3. `trainos/kernel/scheduler/event_scheduler.py`
   - Исправлен вызов `EventBus.publish`: событие передаётся позиционным аргументом, как требует API.
   - `update(now)` теперь публикует только события, время которых наступило.
   - Добавлена проверка типа задачи и наличия `event` в payload.

4. `trainos/kernel/core/runtime/base_context.py`
   - `Lifecycle` создаётся через `field(default_factory=Lifecycle)`, чтобы разные контексты не разделяли один изменяемый объект и модуль корректно работал на Python 3.13.

5. `trainos/kernel/constitution/audit/constitutional_audit.py` и `audit_engine.py`
   - Устранено расхождение имени класса и импорта.
   - `ConstitutionalAudit` теперь совместимый alias канонического `ConstitutionalAuditEntry`, без дублирования dataclass.

6. `trainos/kernel/learning/self_evaluation/improvement_engine.py`
   - Исправлен импорт `ImprovementTarget`: используется уже существующая модель из `kernel.learning.improvement`, вместо отсутствующего модуля.

7. `trainos/tests/kernel_runner/runner.py`
   - Финальное сообщение изменено на `ALL CONFIGURED STAGES PASSED`, потому что список `STAGES` в конфигурации сейчас включает только Stage 38.

8. `pyproject.toml`
   - Добавлен режим импорта pytest `importlib`, позволяющий собирать тестовые файлы с одинаковыми именами в разных каталогах Stage 1–38 при запуске общего набора.

9. Тесты
   - Добавлены тесты стабильности и приоритета `TaskQueue`, обработки событий по времени и независимости жизненного цикла контекстов.
   - Расширены проверки конституционного аудита и импорта improvement engine.

## Важные ограничения / следующие шаги

Это первый проверочный проход, а не заявление, что весь TrainOS функционально завершён.

- `tests/kernel_runner/config.py` по-прежнему включает только Stage 38. Общий запуск pytest проверяет тесты всех стадий; `KernelTestRunner` — только явно сконфигурированные стадии. Это оставлено без автоматического включения 37 стадий, чтобы не менять рабочий процесс без согласования.
- В Stage 38 `HandlerEngine` пока возвращает успешный результат без вызова пользовательской логики обработчика, а `RoutingEngine` оформляет уже выбранный handler, но не выбирает его из реестра. Эти компоненты требуют согласованного контракта, прежде чем превращать каркас в полноценное выполнение.
- В проекте есть и другие методы-заглушки (`pass`, фиксированные `True`/`False`) в разных подсистемах. Не все они автоматически являются дефектами: часть может быть запланированными каркасами будущих стадий. Их следует разбирать по назначению и зависимостям, не заполнять массово.
- `EventBus` в `kernel/events/event_bus.py` вызывает `handler.handle(event)` и проглатывает исключения обработчиков. Это потенциальная проблема API/наблюдаемости, требующая отдельного решения с учётом текущих контрактов.
- Полный набор тестов подтверждает соответствие текущим тестовым ожиданиям, но не доказывает отсутствие всех логических дефектов. Для критичных сценариев нужны интеграционные проверки и явные требования.

## Команда общего прогона

Запускайте из каталога, в котором доступны пакеты `kernel` и `tests`:

```bash
python3 -m pytest tests -q
```

Если проект запускается из внешнего корня репозитория, используйте соответствующий путь к каталогу тестов и настройку окружения проекта.
